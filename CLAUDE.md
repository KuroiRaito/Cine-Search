# Working on Cine Search

A film and TV tracker, live at **bingecon.com**. React 19, Vite, Supabase.
The repo, the directory and the `cine_*` storage keys stay "Cine Search" on
purpose; the product is called Bingecon.

Read this before changing anything that renders.

---

## 1. The one command

```
npm run check
```

verify → states → gallery → gallery:audit → lint → build, stopping at the
first failure. If it is green, you have not broken any of the rules below. If
it is red, read what it says — every failure names the file, the value and
what it expected.

`RUNBOOK.md` has the rest, including how to run one of them on its own and
how to photograph a single control.

## 2. Lanes

| | |
|---|---|
| **Every `.css` file** — shared *and* module | design's lane |
| **Every `.jsx` file** | development's lane |
| `src/shared/ui/Button.jsx` `Chip.jsx` `Segment.jsx` | the seam — read §2.1 |

This is a real boundary, not a preference. A design agent that edits `.jsx`
has changed behaviour nobody reviewed; a development agent that edits `.css`
has changed a system that twenty-four machine checks are holding in place.

If a design fix genuinely requires markup, **say so and stop**.

### 2.1 The three components own three class names

`.btn`, `.chip` and `.seg` are written by `src/shared/ui/Button.jsx`,
`Chip.jsx` and `Segment.jsx` — nowhere else, and `verify` check 19 enforces
that. Before the component layer they were applied by hand at 45, 9 and 3
sites, and a case solved in one file was unknown to the rest.

So a case that used to need markup at twenty call sites now needs one prop in
one file. **Adding a variant is still two changes in two lanes** — the CSS
where the control lives, and the prop that selects it — and a design agent
does the first and says so, rather than doing the second.

Check `docs/CONTROLS.md` C6.3 and C13 before you add a prop. Three bugs were found by
writing those files, all of the same shape: one state spelled two ways in two
places. The chip's was decided by **CSS chunk load order**, and an element
carrying both spellings painted as neither.

## 3. What is authoritative

Three documents, and they answer different questions. Confusing them is the
most expensive mistake available here.

| file | question it answers |
|---|---|
| `docs/design-system.html` | what the design **says** — the Projector specification |
| `docs/as-built.html` | what the code **produces** — generated, never hand-written |
| `docs/CONTROLS.md` | what must be **true** — the contract, numbered C1–C15 |

**`as-built.html` is generated by `npm run gallery` and must never be edited.**
It inlines the product's own stylesheets verbatim and renders the real `Icon`
component, so it cannot drift from the code — that is the whole point of it.
If it looks wrong, the code is wrong.

The specification and the code are checked against each other (`verify` check
18; there are 24 in all) on the 83 tokens the spec declares. **It does not declare the spacing or
radius scales**, so those are not cross-checked — `src/shared/theme/tokens.css`
is the only statement of them.

## 4. The layers, and the one rule about them

```
src/shared/theme/tokens.css   foundations — every colour, length, duration,
                              and the three typefaces, which it also loads
src/shared/ui/ui.css          controls used by more than one module
src/modules/<name>/<name>.css one module's own
src/app/shell.css             journeys — the frame around the modules
```

**A module never repaints a shared control.** Two shapes are allowed, and
the difference is the whole rule:

- **positioning it** — `width`, `height`, `margin`, `padding`, `overflow`.
  How much room the control gets is the parent's business.
- **setting a custom property the control declares** — `--prow-bg`,
  `--noart-size`, `--sheet-pad`. The control still decides what it looks
  like, and the knob is visible in the control's own file.

Changing its `background`, `border`, `radius`, `shadow`, `weight` or
`opacity` from another layer is not allowed, and `verify` check 22 fails it.
A difference that is really a new *variant* is declared where the control
lives, even if only one module uses it. `npm run states` reports the two
counts separately — *repainted* is the violation and is 0.

**Declare a knob as a `var()` fallback, never as a property on the control.**
A custom property set on an element beats the same one inherited from an
ancestor, so `.prow { --prow-bg: var(--surface) }` silently stops `.tside`
from ever setting it. Use `background: var(--prow-bg, var(--surface))`.

## 5. A control is not finished until every case is answered

Three kinds of case, and all three are drawn in the gallery and checked:

- **states** — what it is *doing*: rest, hover, focus, active, disabled, selected, busy, invalid
- **content** — what it is *holding*: the longest label it will really get,
  **the shortest one it will really get**, another script, empty. The short
  end is not symmetry for its own sake — it is where a control with a
  `min-height` stops being the shape it claims to be. See C14.
- **composition** — how *many* of it there are: 0, 1, 2, many

"Answered" includes *deliberately nothing* — but written down, not left out.
`npm run states` prints the coverage table; `npm run gallery:audit` measures
the rendered result.

Content cases must be **real**. Every string in the gallery comes from the
product's own recorded TMDB responses or from TMDB's actual genre names. An
invented 200-character string proves a control *can* be broken; it does not
prove anything *will* break it.

## 6. Two rules that matter more than they look

**Measure, do not assert.** Build the case, render it, read the number. Three
production bugs in this repo survived review because everyone reasoned about
the CSS instead of measuring the box. The plus that looked off-centre was not
off-centre — its button had a 12px content box, and only
`getBoundingClientRect` said so.

**A new check is proved by reinstating the bug and watching it fire.** A check
that has only ever seen a clean tree has not been tested. This is not
ceremony: two checks in this repo passed while completely broken, and only
re-breaking the product found them. One compared a long label against a short
one and measured a difference of zero because both were broken; the other ran
after its own results had already been collected.

## 7. What is NOT covered

Say so rather than assuming the net is wider than it is.

- **`npm run snap` photographs default states only.** 72 screenshots, 7
  screens × 3 widths × 2 themes, all at rest. None of the three bugs that
  reached production would ever appear in it.
- **CI runs `verify`, `lint`, `gallery`, `gallery:audit`, `states`, `build`
  and `test:api`.** So the four measurements are gated now, not just the
  structural checks. Still *not* in CI: `snap`, `auth`, `cohorts`, `find` —
  the behavioural harnesses, three of which need credentials. Run those
  yourself. `states` is in CI for its table and blocks nothing by design.
- **`npm run snap`'s fingerprints are structural, not pixel**, and there are
  **two** of them. `geometry` is every box's position and size — that is the
  "did anything move" question. `hash` is the same thing plus each element's
  class list, so **it moves when a class is renamed even though nothing moved
  on screen.** Read `geometry` to judge a refactor; `hash` only tells you the
  markup changed, which you already knew. Neither says anything about colour
  — read computed styles for that. Dark and light shots share a value, which
  is why only 36 of the 72 are distinct.
- **No search screenshot contains a chip.** The photographed search screen
  has no filter applied, and `.chips:empty` is `display: none`. The chip is
  covered only through Library's shelf row.
- **`as-built.html` carries the typefaces as base64, and only Latin.** The
  product loads its faces with `@import '@fontsource/…'`, which only a bundler
  resolves — inlined into a plain HTML file those specifiers are dead, and a
  font that fails to load fails *silently*. So `gallery` expands them into
  data URIs, `latin` and `latin-ext` only, upright only. **Any specimen in a
  script outside those subsets is measured in a fallback face** — the
  Devanagari chip always was, since IBM Plex Sans has no Devanagari in these
  files. Widen `KEEP` in `scripts/gallery.mjs` when a specimen needs more.
- **Non-Latin product text renders in a fallback face**, so a Hangul or
  Devanagari title sits in a different typeface from the UI around it. IBM
  Plex has Devanagari, JP and KR siblings if that is ever worth the bytes.
- **Accessibility beyond focus order is unchecked.** Contrast is designed, not
  verified.

## 8. Writing it down

Commit messages here carry the *reasoning*, not a summary of the diff — what
was measured, what the number was, what was considered and rejected. The
history is the only place that survives, and several commits exist mainly to
record a mechanism somebody will otherwise rediscover the hard way.

Comments in the stylesheets do the same job. If a declaration is load-bearing
for a non-obvious reason, the reason goes next to it.

## 9. Process

Concept → design → grooming → development. **No development starts until
grooming closes.** The plan of record is `docs/AUDIT_2026-09-13.md`.

Supabase writes go through RPC. There is no service-role key, and
`SECURITY DEFINER` functions guard the shared catalogue — see
`docs/SECURITY.md`. Never commit `.env`.
